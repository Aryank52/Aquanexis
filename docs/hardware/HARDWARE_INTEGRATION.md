# AquaNexis — Hardware Integration & Edge Protocol Specification

**Target Hardware**: ESP32-WROOM-32D / ESP32-S3  
**Protocol Version**: Canonical Wire Contract v1.0  
**Transport**: HTTPS POST / WSS (WebSocket Secure)  

---

## 1. Unified Canonical Telemetry Wire Contract

All edge devices stream sensor readings to the ingestion endpoint:

`POST /api/v1/telemetry/canonical`

### Canonical JSON Payload Specification:

### Telemetry Provenance Rules:
- **`MEASURED`**: Physical readings origin from authentic ESP32 hardware sensors. Requires verified Bearer device token.
- **`SIMULATED`**: Synthetic telemetry generated by the Python simulator or in DEMO_MODE.
- The server will **never** silently upgrade `SIMULATED` readings to `MEASURED`.

## 2. Device Provisioning & Authentication Protocol

Edge devices authenticate using signed JWT tokens with device claims:

### Provisioning Request:
`POST /api/v1/devices/provision`
```json
{
  "serial_number": "AQX-ESP32-2026-0084",
  "model": "AquaNexis-Edge-ESP32",
  "firmware_version": "v1.2.0",
  "display_name": "Kitchen Purifier Unit #4"
}
```

### Provisioning Response:
```json
{
  "device_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "serial_number": "AQX-ESP32-2026-0084",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in_days": 365,
  "server_time": "2026-11-04T12:00:00.000Z"
}
```

The device stores this token securely in Non-Volatile Storage (NVS) and includes it in all requests:  
`Authorization: Bearer <TOKEN>`

## 3. Edge Security Protocol

1. **Replay & Sequence Protection**:
   - The device increments `sequence_number` strictly monotonically ($seq_{n} > seq_{n-1}$).
   - Duplicate or decreasing sequences are rejected with HTTP 409 Conflict.
2. **Clock-Skew Defense**:
   - Server validates $|t_{\text{packet}} - t_{\text{server}}| \le 300\text{ seconds}$.
   - Excessively skewed timestamps are rejected with HTTP 422 Unprocessable Entity.
3. **Per-Device Authorization**:
   - The token claim `device_id` must match the payload `device_id`.
   - Mismatches are rejected with HTTP 403 Forbidden.
4. **Offline Buffering**:
   - When Wi-Fi or cellular connectivity drops, readings are stored in a SPIFFS/LittleFS flash ring buffer with monotonically assigned sequence numbers.
   - Upon reconnect, the device sends buffered packets with `is_buffered=true`.

## 4. Hardware Sensor Pinout & Wiring

| Sensor Function | Sensor Part Number | Interface | ESP32 GPIO Pin | Operating Voltage |
| :--- | :--- | :--- | :---: | :---: |
| **Total Dissolved Solids (TDS)** | Gravity Analog TDS Sensor | ADC1 (Ch 6) | `GPIO 34` | 3.3V / 5V |
| **pH Sensing** | Gravity Analog pH Probe | ADC1 (Ch 7) | `GPIO 35` | 5.0V |
| **Turbidity Sensing** | TSW-20M Optical Turbidity | ADC1 (Ch 4) | `GPIO 32` | 5.0V |
| **Temperature** | DS18B20 Waterproof | 1-Wire (4.7kΩ pullup) | `GPIO 4` | 3.3V |
| **Feed Flow Rate** | YF-S201 Hall Effect Sensor | Hardware Pulse Counter | `GPIO 18` | 5.0V |
| **Inlet Pressure** | 0–1.2 MPa Piezoresistive | ADC1 (Ch 5) | `GPIO 33` | 5.0V |
| **Outlet Pressure** | 0–1.2 MPa Piezoresistive | ADC1 (Ch 0) | `GPIO 36 (VP)`| 5.0V |
| **Leak Detection Probe** | Gold-plated contact comb | Digital Interrupt | `GPIO 19` | 3.3V (Pullup) |
| **Inlet Solenoid Valve** | 12V DC Normally Closed | Optocoupled Relay | `GPIO 23` | 3.3V Logic |
| **Booster Pump Power** | Solid State Relay (SSR) | Optocoupled Relay | `GPIO 22` | 3.3V Logic |
